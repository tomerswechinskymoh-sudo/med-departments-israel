## השינויים

### זהות ואחריות

נוסח אחריות משרד הבריאות אוחד בתנאי השימוש, פרטיות, אודות, FAQ, קשר, נגישות והרשמה. סעיפי האחריות הותאמו בלי להבטיח מידע נטול טעויות. הקרדיט ליוזם/מפתח ודרך הפנייה הקיימת נשמרו, ללא ייחוס תפקיד ממונה פרטיות או רכז נגישות. לא נוצר מאגר חדש, לא הומצא מספר רישום ולא נקבע פטור מרישום.

חובת הגשת חוויה נשארה לשש־שנתי משנה ד׳, ארבע־שנתי משנה ג׳, סטאז׳רים ומתמחים; הפטורים, העדר דילוג, פרסום ללא שם וההגשה לבדיקה נשמרו. פרסום בפועל לא נוסף כתנאי להרשמה. מודרציה, דיווחי פגיעה והחלטות פרסום לא שונו.

### מחיקת מסמכים

המיגרציה מוסיפה trigger ו־`delete_signup_documents` במסד. שינוי ל־VERIFIED או REJECTED ומחיקת כל גרסאות מסמך ההרשמה הבלעדיות מתבצעים באותה טרנזקציה. כשל מחיקה או שיוך עמום מבטל גם את ההחלטה; האדמין מקבל שגיאה מפורשת ויכול לנסות שוב. נרשם אירוע כשל מינימלי ב־AuditLog. אין retry אסינכרוני נפרד כי אין פיצול בין המסד לאחסון חיצוני.

נבדקים קטגוריה, בעלות, פרטיות, הפניות למחלקה/משרה/מועמדות/חוויה, הפניות זהות/ייבוא בסבבים קליניים והפניות משתמש נוספות. מקרה משותף או עמום אינו נמחק אוטומטית. בניקוי המדורג נשמר עבורו אירוע לבירור. תוכן הקובץ, שמו והכתובת אינם נשמרים בתיעוד המחיקה או בשגיאה. ההפניה מהמשתמש מתאפסת; נשאר רישום מחיקה מינימלי עם מזהה משתמש, סטטוס, מספר מסמכים ומועד.

העלאה והחלטה נועלות את אותה רשומת משתמש: אם ההעלאה סיימה ראשונה, ההחלטה מוחקת אותה; אם ההחלטה סיימה ראשונה, ההעלאה המאוחרת נדחית. המחיקה idempotent. אישור דוא״ל מאוחר אינו יכול להחזיר חשבון שהוכרע למצב ממתין. `/api/files` חוסם גם מסמך היסטורי שעדיין לא נוקה כאשר בעליו כבר הוכרע, לרבות לאדמין; תגובות הקובץ הן no-store. ממתינים ואסמכתאות לחוויות נשמרים.

הנוסח הציבורי מתאר מחיקה מהמערכת הפעילה, מציין במפורש שניקוי הרשומות ההיסטוריות טרם אושר כהושלם, ואינו מבטיח מחיקה מיידית מגיבויים.

### מתגי המקורות

`SourceVisibility` הוא singleton עם שני דגלים עצמאיים ו־revision. ברירת המחדל במיגרציה היא true לשניהם. פעולת PATCH מחייבת אדמין בשרת ובדיקת same-origin. בממשק שני switches עם שם, מצב, שמירה בלחיצה אחת ומשוב הצלחה/כשל.

הסינון משתמש במפתחות הנתונים ובהפניות מקור קיימות, לא ב־CSS או בטקסט הכותרת. מקור כבוי מוסר לפני חישוב מדדים, כרטיסים, השוואות וגרפים; חסר אינו הופך לאפס ודירוגי החוויות נשמרים. מיפוי התמחויות ותיאורי הר״י שהיו כלולים בחבילת הלקוח הועברו למודול שרת ומועברים ללקוח רק כאשר המקור פעיל. נתוני המקור במסד ובכלי האדמין נשמרים. מסלול debug שהיה פתוח בפיתוח מחייב כעת אדמין תמיד.

כל קריאה ציבורית מקבלת את ההגדרות העדכניות; revision נכלל במפתח המטמון. שמירה מנקה את מטמון הזיכרון ומבטלת את תגיות Next וה־layout. מסלולים אלה דינמיים. עותק שכבר הורד לדפדפן או נשמר מחוץ למערכת אינו ניתן להחזרה בדיעבד; השינוי חל על בקשות חדשות לאחר השמירה.

`sendMarketingEmail` בודק זכאות במסד מיד לפני מסירה לספק, תחת אותה נעילת משתמש של ביטול ההסכמה. הודעה שהוכנה קודם אינה נשלחת לאחר שהביטול נשמר. שליחה שכבר התקבלה אצל הספק לפני הביטול אינה ניתנת לביטול בדיעבד. לשיווק יש כותרת ״פרסומת״, שם משרד הבריאות, כתובת מפרסם, כתובת סירוב תקפה וקישור ביטול. בהיעדר כתובת מפרסם וכתובת דוא״ל מאומתות, השיווק נכשל לפני שליחה. לא נוסף bypass לרשימות תלונות/כשלי מסירה של Resend, ולא שונו הגדרות הספק. מסירה אמיתית ו־webhooks של הספק לא נבדקו.

### נגישות

בטופס החוויה: label מקושר ל־input טבעי עם `useId`, הוראות ב־aria-describedby, ההוכחה הציבורית נשארה רשות. בחירת סוג משתף היא radio טבעי בתוך fieldset/legend, כולל פוקוס נראה. במעבר קדימה ואחורה הפוקוס עובר לכותרת השלב; מוצגים מספר השלב ו־aria-current. לא נוסף live region לכל הטופס. במהלך הסריקה נמצאו גם תוויות חסרות בטופסי שחזור סיסמה: נוספו תוויות, קשר לשגיאות ומשוב.

נשמרו ונבדקו קישור הדילוג, פוקוס התחלתי בחלון, לכידת Tab, Escape והחזרת פוקוס, חלונית הסבר מספר המתמחים, FAQ, רדיו ופוקוס בשאלון. נבדקו מתגי המקורות והעדפות הדיוור, כולל כשל שמירה שאינו מציג הצלחה שגויה. בכוכבי הדירוג נשמר הציון המספרי והשם הנגיש; בהירות כוכב דקורטיבי לא סווגה כשלעצמה כהפרה.

## הפעלה וניקוי היסטורי — לביצוע בסביבה המאושרת

לפני פריסה, להחיל את המיגרציה על המסד הנכון באמצעות ההגדרות הקיימות. אין להפעיל `migrate dev` או fixtures על production. מומלץ חלון תחזוקה קצר כדי שהקוד החדש וטריגרי המסד יופעלו יחד.

```sh
npm ci
npm run prisma:migrate:deploy
npm run build
npm run cleanup:signup-documents
```

הפקודה האחרונה היא dry-run בלבד: ספירות לפי מצב, מסמכים בלעדיים/עמומים, יתומים והפניות לא פתורות; אין מזהי משתמשים או תוכן בפלט. לאחר בדיקת התוצאה ואישור מפעיל מוסמך:

```sh
npm run cleanup:signup-documents -- --execute --confirm-reviewed-dry-run --batch-size=50
npm run cleanup:signup-documents
```

כל הפעלה מעבדת לכל היותר אצווה אחת, ונועלת ובודקת שוב מצב, מטרה והפניות לפני מחיקה. חוזרים באצוות עד שאין מסמכים זכאים במצבים סופיים; ממתינים נשארים. exit 2 מציין כשל/מקרה שדורש בירור, ו־exit 1 כשל כללי. יש לבדוק ב־AuditLog את `signup.document_cleanup_failed` ו־`signup.document_cleanup_review_required`, לברר שיוך ולהריץ שוב אחרי תיקון מאושר. אין לשנות קטגוריה או להסיר הפניה רק כדי לגרום לניקוי לעבור. יתום/כתובת חיצונית אינם נמחקים בעיוורון.

ה־dry-run והביצוע המוגבל נבדקו מקומית בלבד. אין בדוח ספירות production. אחרי השלמת הניקוי בפועל יש לעדכן רק את המשפט הציבורי על מצב הניקוי ההיסטורי; אין להסירו על בסיס הצלחת בדיקות בלבד.

## גיבויים ומניעת חזרה לאחר שחזור

ב־10.11.2026 בוצעה בדיקת מטא־נתונים בקריאה בלבד בפרויקט Neon ששמו תואם לשם הפרויקט בריפו: `history_retention_seconds=21600`, כלומר שש שעות PITR. רשימת snapshots הייתה ריקה ולענף המסומן production לא הוגדר snapshot schedule. נמצא גם ענף ולידציה קודם שנוצר מעותק parent-data. לא נקראו מסמכי משתמשים ולא שונו פרויקט, ענף, ספק או הגדרת גיבוי. ההתאמה לכתובת החיבור של פריסת production לא נבדקה באמצעות סוד פריסה, ולכן יש לאשר אותה תפעולית; הממצאים אינם הוכחה שאין exports, ענפים או גיבויים אחרים.

DELETE מסיר את הרשומה ואת התוכן הפעיל; אין הבטחה למחיקה מיידית מ־PITR/WAL, מגיבויים, מענפי בדיקה ישנים או מהורדות שבוצעו בעבר. יש לכלול במיפוי התפעולי כל עותק קיים, להריץ עליו dry-run מאושר ולתאם ניקוי לפי מדיניותו. המימוש אינו מוחק אוטומטית ענפי Neon אחרים.

נוהל שחזור מחייב: להשאיר את השירות המשוחזר סגור עד השלמת התאמה. לפני השחזור, להקפיא החלטות והרשמות ולייצא מהמצב הסמכותי העדכני את יומן המחיקות המינימלי למיקום מאובטח קיים, מחוץ לתיקיית אתר/גיבוי שמוחלף. המשתנה להלן הוא נתיב קובץ שיקבע המפעיל, לא כתובת חדשה או ספק חדש:

```sh
npm run restore:signup-deletions -- --export="$SIGNUP_DELETION_LEDGER"
```

הקובץ כולל רק מזהה משתמש, סטטוס ומועד; נכתב בהרשאה 0600, ללא overwrite, ולא מודפס למסך. אין להכניסו ל־Git או לדוח. לאחר שחזור מבודד, להחיל את המיגרציות ואז:

```sh
npm run restore:signup-deletions -- --replay="$SIGNUP_DELETION_LEDGER"
npm run restore:signup-deletions -- --replay="$SIGNUP_DELETION_LEDGER" --execute --confirm-offline-reviewed-dry-run
npm run cleanup:signup-documents
```

Replay נועל ובודק שוב את המשתמש, משחזר רק החלטה מתועדת שהרישום הנוכחי אינו מאוחר ממנה, ומפעיל את אותה מחיקה אטומית. הרשמה/החלטה מאוחרת יותר נשארת; מסמך חדש יותר או שיוך עמום עוצרים לבירור. לאחר מכן משלימים ניקוי באצוות ומוודאים העדר מסמכים סופיים והעדר מקרים לא פתורים לפני פתיחה. בדיקות סינתטיות מאמתות מחיקה חוזרת, שמירת הוכחת חוויה ושמירת הרשמה חדשה.

אם אין יומן סמכותי עדכני, אי אפשר לזהות מקוד בלבד אילו ממתינים בגיבוי כבר הוכרעו לאחריו. אין לפתוח מחדש הורדת מסמכי אימות עד שחזור ההחלטות ממקור מוסמך ובדיקת התאמה. הנוהל אינו hook אוטומטי של ספק הגיבוי; יש לשלבו בנוהל התפעול הקיים.

## השלמות ארגוניות

1. נדרש לוודא עם הגורם המוסמך במשרד הבריאות שהפעילות מכוסה ברישום מתאים, לרבות האפשרות שהיא כבר נכללת במאגר משרדי רשום. זו אינה פעולה שניתן להשלים בקוד.
2. לא אומתו פרטי ממונה הגנת הפרטיות/רכז נגישות מוסדיים המוסמכים לטפל באתר. דרך הפנייה הקיימת נשמרה, ללא פרסום תפקיד או placeholder.
3. לפני דיוור שיווקי יש לאמת כתובת מפרסם וכתובת פעילה לקבלת סירוב ולהגדיר `MARKETING_ADVERTISER_ADDRESS` ו־`MARKETING_REPLY_TO`. השער החדש מונע שליחה בהיעדרם. יש לשמור על מפתח האימות הקיים כך שקישורי ביטול שנשלחו ימשיכו להיות תקפים בעת ניהול מפתחות.
4. יש לבצע ולתעד ניקוי היסטורי מדורג בסביבה המורשית, כולל בירור עותקים בענפים/גיבויים קיימים, ולהטמיע את נוהל השחזור לפני שימוש בו.
5. נותרו בדיקות נגישות מקצועיות עם קורא מסך, זום אמיתי, מובייל פיזי ונתוני שימוש אמיתיים. אין להתייחס למעבר axe כהסמכה.
