# סקר הסטאז׳ — ייבוא פרטי ואישור חוויות

הממשק נמצא ב־`/admin/survey-reviews` ונוסף קישור בדשבורד האדמין. מקור הנתונים הוא `STAZ_SURVEY_2020_2025`. כל רשומה חדשה ממתינה לבדיקה, `publishText=false`, `publishRatings=false`, ללא יעד מאושר. מקור הסקר מתחיל כבוי וללא אישור שימוש.

## נתונים ואימות מקור

הארכיון שנמסר כולל שמות קבצים שונים מהשמות במפרט: `staz_survey_processed_download.xlsm`, `staz_positive_reviews_download.csv`, `codex_staz_prompt_download.md`. המפרט נקרא במלואו. קובצי המקור נשארו מחוץ לריפו ולארטיפקט הפריסה; אין הפעלת מאקרו.

- 3,608 מועמדות חיוביות: 1,572 בעמודת BL, ‏1,284 בעמודת BP ו־752 בעמודת BG.
- 2,043 ציוני המלצה אישיים תקפים, באותה שורת מקור ובהקשר האלקטיב המתאים: BL↔BK או BP↔BO.
- 813 תגובות אלקטיב ללא ציון 1–5 תקף; 752 תגובות כלל־בית־חולימיות ללא דירוג מחלקה. בסך הכול 1,565 ללא דירוג מחלקה מתאים.
- 193 הבדלי טקסט בין CSV ל־XLSM היו רווחים או מעברי שורה בלבד. תוכן הטקסט, בית החולים, המחלקה והשנה אומתו בכל 3,608 המועמדות. טקסט המקור נשמר בנפרד מההצעה המעובדת.
- 808 הצעות שיוך בטוחות ליעד יחיד בקטלוג הציבורי הפעיל; 2,800 דורשות בירור/בחירה ידנית. גם הצעה בטוחה אינה אישור שיוך. רשומות מורשת שאינן מוצגות באתר אינן יעדי פרסום תקפים.
- אין שימוש בממוצעים מהגיליונות המעובדים, במדדי סבבי החובה, או בציוני בית חולים כציוני מחלקה.

## שימוש באדמין

1. קוראים את התגובות ישירות ברשימה הרציפה. כל כרטיס מציג טקסט, בית חולים ומחלקת מקור, מחלקה מוצעת וציון המלצה. תגובות נוספות נטענות בגלילה.
2. הצעת שיוך קיימת כבר נבחרת בכרטיס. אפשר להחליף אותה; בחירה ידנית נדרשת אם אין הצעה בטוחה. מעבר למוסד אחר/מוסד לא מזוהה דורש נימוק חריג. תגובה על כלל בית החולים דורשת נימוק שיוך ותישא תווית הקשר ציבורית.
3. בודקים פרטיות ועורכים טקסט במידת הצורך, ללא שינוי משמעות. הכיתוב ליד הפעולות מבהיר שלחיצה מאשרת בדיקה ידנית של השיוך והפרטיות ברכיב הנבחר.
4. לוחצים בנפרד על **פרסום תגובה** ועל **פרסום ציון המלצה**. כל כפתור מאשר רק את הרכיב שלו בלחיצה אחת, בלי לפתוח חלונית או לסמן תיבות נוספות. לכל מדד כפתור משלו; ביטול אישור אפשרי בנפרד. הכרטיס נשאר במקום כדי לאפשר את הפעולה השנייה.
5. אישור כשהמקור כבוי אינו מפרסם אותו. אישור הרכיב השני שומר על הראשון אם השיוך לא השתנה. שינוי מחלקה מחייב אישור חדש לרכיב השני. עריכת טקסט אינה נשמרת או מאושרת בלחיצה על פרסום ציון. חלונית **מקור ואפשרויות נוספות** זמינה לבדיקה מפורטת, דחייה ושמירת טיוטה; במסלול העריכה המלא שינוי פריט מאושר עדיין מחזיר אותו לבדיקה.
6. רק לאחר היתר שימוש אמיתי ומתועד מבעל השליטה בסקר, מתעדים אותו בחלונית הזכויות. רישום ההיתר משאיר את המקור כבוי; ההפעלה היא פעולה נפרדת ומפורשת.
7. הסתרה אינה ממתינה לנעילת ייבוא ארוך; שינוי זכויות/הפעלה משתמש בבקרת גרסה כדי למנוע דריסה של הסתרה במקביל. הכפתור **הסתר את כל חוויות סקר הסטאז׳ מהאתר** מכבה את כל תוכן המקור בלי למחוק רשומות או החלטות. הפעלה מחדש מחזירה רק פריטים מאושרים. ביטול היתר שימוש מכבה את המקור.

CSV ניתן להעלות בממשק עד 3MiB, לקבל דוח לפני קליטה ואז לאשר קליטה לתור. CSV לבדו אינו ראיה לציון: רשומות חדשות ממנו חסומות לאישור עד להצלבת XLSM בייבוא המקומי. הייבוא הראשוני של החבילה המלאה מבצע הצלבה זו מראש.

## מודלים, הרשאות ותצוגה

המיגרציה `202611120001_staz_survey_reviews` מוסיפה את `SurveyReviewSource`, `SurveyReviewImport`, `SurveyReview`, `SurveyReviewRating` וסטטוסי תור. היא טרנזקציונית, בעלת זמני המתנה מוגבלים ואילוצי DB לפרסום, טווח ציונים ואיסור דירוג מחלקה ל־BG. `Department` מקבל קשר לתור הסקר. נעשה שימוש ב־`AuditLog` הקיים.

`Review` ו־`ReviewSubmission` הקיימים דורשים שדות כגון טלפון ושישה ציונים מלאים; לכן אין יצירת משיב, אימות או ציונים מלאכותיים. התור הפרטי מוזן דרך מתאם שרת אל `DepartmentExperienceTabs` ו־`ReviewCard` הקיימים. זהו אותו אזור חוויות ואותה שפה עיצובית. מדד המלצת האלקטיב מחושב בנפרד, ורק מהמדדים שנבחרו ואושרו. דירוג בלבד אינו יוצר כרטיס טקסט ריק. חוויות המשתמשים, חובת החוויה בהרשמה, הממוצעים הקיימים, השוואות וסדרי חיפוש נשמרים.

כל מסכי/API הניהול דורשים אדמין בצד השרת. פעולות שינוי דורשות Origin תואם; גודל גוף הבקשה מוגבל גם בזרימה. React מציג טקסט מוחרג ועריכות מנוקות כטקסט פשוט. מקור התגובה מוצפן ב־AES-256-GCM בעזרת מפתח הסקרים הקיים, עם קשירה למפתח הרשומה. תאריכים מלאים ונתונים דמוגרפיים מהגיליון אינם מיובאים.

שאילתת הפרסום היחידה בודקת באותה קריאת DB: מקור מופעל, היתר, אישור פריט, פרטיות, מקור מאומת ושיוך למחלקה פעילה. היא אינה נשמרת במטמון. שינוי החלטה/מקור מבטל את מטמון הנתיבים. תגובות המקור אינן נכתבות לטבלאות הדירוגים המאומתים ולכן אינן יכולות לדלוף דרך חישובים, API, חיפוש או SEO קיימים. בדיקת השרת אינה יכולה למחוק תוכן שכבר נמסר לדפדפן קודם לכן; בקשות ורענונים חדשים נאכפים מול מצב המקור הנוכחי.

## ייבוא חוזר

מפתח הרשומה הוא מקור + שורת מקור + עמודת מקור. אותו מפתח אינו מוכפל. שינוי בטקסט/נתוני מקור או בראיות הדירוג מדווח כקונפליקט והגרסה והחלטות האדמין הקיימות נשמרות. אין דריסה של החלטות. ניתן להעשיר רשומת CSV שטרם אומתה באמצעות אותו מקור XLSM תואם; הדבר אינו בוחר או מאשר שום רכיב פרסום.

באמצעות סביבת שרת מוגנת, ללא סודות בארגומנטים:

```sh
npm run survey:staz -- dry-run --csv /private/candidates.csv --workbook /private/source.xlsm
npm run survey:staz -- import --csv /private/candidates.csv --workbook /private/source.xlsm
```

## נתיבים וקוד

- `/admin/survey-reviews` — תור, חיפוש, מסננים, דוחות, בדיקת פריט וזכויות מקור.
- `/api/admin/survey-reviews` — רשימה, מונים, קטלוג ומסננים.
- `/api/admin/survey-reviews/[id]` — ראיות המקור הפרטיות והחלטה יחידה עם בקרת גרסה.
- `/api/admin/survey-reviews/import` — בדיקה וקליטת CSV.
- `/api/admin/survey-reviews/source` — הסתרה, הפעלה ותיעוד/ביטול היתר.
- `src/server/staz-survey/` — ייבוא, הצלבה, החלטות, אבטחת HTTP ומתאם ציבורי.
- `src/lib/staz-survey/domain.ts` — הקשר שאלה/ציון וכללי הצעת שיוך מפורשים.
- `scripts/staz-survey/` — CLI, בדיקת ייצור, דוח מצרפי ותהליך הפריסה.
- `tests/staz-survey/` — נתונים סינתטיים בלבד, בדיקות יחידה, DB, הרשאות ודפדפן.

## בדיקות ופריסה

8 בדיקות יחידה/רגרסיה חדשות כוללות השוואת HTML של חוויות משתמשים למימוש הקודם. 11 בדיקות הסקר החיצוני הקיים ו־9 בדיקות העלאות/הגנת פריסה עברו. בדיקת הקובץ האמיתי של הסקר האחר דולגה משום שאינו חלק מהחבילה. חבילת האינטגרציה הישנה לפרטיות דורשת PostgreSQL מקומי ייעודי שלא היה זמין; היא לא הורצה בהצלחה בסביבה זו. בדיקות ה־DB החדשות הורצו בענף Neon מבודד, עם תוכן סינתטי וחתימות לפני/אחרי לחוויות ולמדדים הקיימים.

בדיקות החדשות מכסות מקור כבוי, זכויות חסרות, טקסט בלבד/דירוג בלבד/שניהם, BL/BK ו־BP/BO, ‏BG, שגיאות שיוך, מדד מרשומה אחרת, פרטיות, גרסה ישנה, שינוי אחרי אישור, דחייה, ייבוא חוזר, הסתרה/החזרה וביטול זכויות. נבדקו הרשאות HTTP, ‏CSRF, ‏no-store, תצוגת מחלקה, היעדר נתונים לאחר הסתרה בעמודי מחלקה/בית/חיפוש/השוואה/API/sitemap, ו־4 סריקות נגישות/גלילה ב־1440 וב־375 פיקסלים. אלו בדיקות אוטומטיות, לא בדיקה במכשיר פיזי או בקורא מסך.

ענף הבדיקה: `br-round-wave-ama202vn`. נקודת שחזור ייצור לפני המיגרציה: `snap-jolly-butterfly-amkwbqp9`. תהליך Vercel נשמר: ארכיון קומיט בלבד, פריסה עם `--skip-domain`, אימות READY וקובצי המקור, בדיקות, קידום לשני הדומיינים, וסנכרון GitHub תוך מניעת פריסה כפולה. סודות, CSV ו־XLSM אינם בארכיון.

קבלות הפריסה והמספרים בפועל נכתבים לקובצי הדוח הנלווים. ביטול גרסת קוד מתבצע באמצעות חזרה לפריסת Vercel הקודמת; אין למחוק את טבלאות התור או החלטות האדמין לשם rollback.
