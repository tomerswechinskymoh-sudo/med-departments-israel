# Phase 4A methodology — 2026-10-01.1

Exploratory beta, original preference questions; no validation, institutional endorsement, ability assessment, medical advice, admission prediction or quality ranking. Configuration: `src/lib/career-fit/config.ts`; pure evaluation: `scoring.ts`. No proprietary assessment items or scoring keys were accessed or reproduced.

## Sources and editorial review

Retrieved 2026-10-01. AAMC Personal Attributes (https://careersinmedicine.aamc.org/understand-yourself/personal-attributes) supports separating interests and values. Finding Your Fit (https://careersinmedicine.aamc.org/choose-your-specialty/finding-your-fit) supports exploration across multiple considerations and cautions against stereotypes. Used only as design context, not evidence validating this algorithm.

IMA taxonomy https://www.ima.org.il/internship/Specializations.aspx distinguishes base, subspecialty and fellowship. Sixteen individual official training pages are linked per profile. Each mapping is an editorial interpretation of named training settings/activities, NOT a numeric measurement of specialty performance/frequency. Presence is supported; absence is UNKNOWN, never interpreted as low/absent activity. Optional rotations do not prove universal daily work. Department categories are not official pathways. Radiology, emergency medicine and rehabilitation have base and subspecialty routes; psychiatry additionally has a route for family-medicine specialists without being relabeled a subspecialty. The source controls prerequisites; this tool does not assess eligibility. Fellowship/subspecialty-only fields have no direct-entry recommendation profile.

Source snapshots are local under `/private/tmp/hitmachut-phase4a/ima-*.html` and `.txt`; individual interpretation, supported and missing dimensions, limitations, version, URL are in every profile. Sixteen profiles are partially characterized; dermatology, neurology and rehabilitation have only two mapped dimensions. Fifteen other official base specialties are explicitly unprofiled. Live catalog labels without a reviewed match are also listed. No cross-project ENT data imported.

## Specialty formula (fixed before tests)

28 questions in four sections. Answers 0..4 map to 0..1. Unknown and skipped are missing; 2 is an informative midpoint. For each dimension, mean its known items: item count never increases dimension weight. User weights 0,1,2,3 are separate; default 1. Research/teaching and investigation considerations never enter specialty matching. Scored set is the explicit 14-dimension allowlist; no demographics, education location, prestige, salary, workload or acceptance inputs.

Require >=10 answered scored items and >=6 active dimensions. For each profile: W=sum weights across ALL answered active dimensions; known contribution c_d=w_d*u_d/W; coverage=sum weights with mapped profile evidence/W. Eligibility requires >=2 mapped active dimensions, coverage >=0.20, and >=2 mapped interests with u>=0.75. These are conservative editorial gates, not empirically calibrated cutoffs. The lower support bound L=sum c_d, upper U=L+(1-coverage) represent unresolved evidence, NOT confidence/probability. Unknown values are never replaced by zero preferences. A suggestion is omitted only if another eligible profile's L strictly exceeds its U (epsilon 1e-10). Overlapping intervals remain unresolved; stable Unicode label order is navigation only, not a clinical ranking. Identical profiles tie. At most five cards initially; all remaining unresolved directions can be expanded without arbitrary top-five exclusion. No fit percentages displayed. Every explanation uses actual contribution records, with weights and original mean scale values; lower preferences and missing dimensions remain visible. If gates fail, only summary and further exploration prompt.

## Department availability and formula (fixed before tests)

Eight preference controls; only three supported dimensions: region (`Institution.region`, recognized normalized value only, NO default-to-center inference), preferred institution (`Department.institution.id/name`) and institution type (`Institution.type`, HOSPITAL/HMO). Public department universe reuses `getDepartmentOptions`, including its existing catalog visibility restrictions; this tool cannot claim all Israeli departments. Additional query selects department id and institution name/region/type for already-public department IDs. Directory identities are effective hospital IDs, not database institution IDs. Region/type are attached only when original and public institution names agree (NFKC/trim); reassignment or uncertain identity remains unknown. Year/update date unavailable; retrieval date is not observation date. Per-specialty completeness is computed from response values and shown. A public source link points to each existing department page. No patient surveys/review scores/raw respondents fetched.

Unavailable: clinical exposure (no comparable structured measure); research opportunities (no opportunity measure); total team size (partial rosters/new-resident/yearly measures not equivalent); teaching/mentorship and work environment (public comparable respondent category/date/N/scope not established). Survey averages are deliberately excluded rather than mixing students and residents. No professor, publication, fellowship, beds, Duns, operative-volume, patient-survey, wait-time or demand proxies. The full versioned preference→field→scope→limitation map is `availability` in config and public methodology.

Only explicit hard filters exclude: known mismatch→excluded; missing requirement→unverified unless another known hard mismatch excludes. Hard filters are separate from soft weights. Unknown is neither pass nor proven failure. Soft score=sum(w_i * exactMembershipMatch_i)/sum(all selected supported soft weights). Rank ONLY when 100% of selected soft weight is known; sparse rows are placed separately with null score. Denominator never shrinks. Rank ties share an explicit label; ID is merely stable tie display order. No soft metrics→filter-based facts, no rank. Unsupported preferences do not affect denominator, gates, exclusion or ranking. Scores are internal ordering, not universal quality. Only required filters may remove departments from eligible consideration; insufficient/unverified lists remain accessible.

## Privacy

React memory only. No optional persistence in v1; no local/session storage, cookies, account profiles, server writes or answer analytics. Reload/navigation away clears answers; module-internal continuation keeps state in memory. Only an answer-independent GET to `/api/career-fit/catalog` fetches a whitelist of public facts. No answers or priorities in URLs; links contain only public catalog identifiers. No runtime AI. Existing site authentication remains unchanged for comparison/restricted pages; this statement applies to the module, not the entire site. No migration, flags, placements or representatives changed.
